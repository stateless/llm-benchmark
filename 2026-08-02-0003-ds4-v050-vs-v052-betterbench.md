
# Report card — engine A/B: Entrpi ds4 v0.5.0 vs v0.5.2 (DS4-Flash-0731 DSpark, BetterBench)

> **BetterBench** — a serving-perf sweep with **server-truth token counts** (usage from the stream, no client
> tokenizer). This is an **engine A/B**: the ONLY variable is the ds4 version. Held constant: weights (0731
> IQ2XXS), drafter, ctx 32768, full-residency, and the BetterBench corpus/sampling. Sequential arms on one GB10.

**Why:** v0.5.2 is a field-robustness fast-follow (dead-client abort, deep-`-c` serial serving, MTP accept guard,
disk-KV restore, trim-on-evict) whose release notes claim **"no performance re-bases — byte-exact serving twins."**
This is the neutral-harness check on that claim for the hot path (short ctx, cold nonce, full-residency — *not*
the disk-KV/deep-serial paths those fixes target), plus whether the memory right-sizing shifts the concurrency ceiling.

**Provenance (locked):** engine A `Entrpi/ds4@v0.5.0` (`d9c8587`) · engine B `@v0.5.2` (`82d2a6f`), both built
`sm_121a` via `make cuda-spark`. Base `antirez/deepseek-v4-gguf …IQ2XXS…-0731.gguf` (81 GiB) + drafter
`bleysg/…DSpark-drafter-Q2K-Q8-0731.gguf` (6.5 GiB), DSpark, ctx 32768. Harness BetterBench `@365594755a`
(corpus v1.0, temp 0.7, 20 runs/cat, cold nonce).

## Results

| axis | v0.5.0 | v0.5.2 | Δ / note |
|---|--:|--:|---|
| **combined decode t/s** | 28.9 | **30.1** | +4% (within n=1 noise) |
| combined TTFT p50 | 701 ms | **624 ms** | v0.5.2 lower |
| **DSpark accept** (median) | 76.6% | 77.4% | ≈ equal (274 / 276 batches) |
| prefill PP t/s @32k | 964 | **1053** | v0.5.2 holds throughput at depth |
| concurrency agg @1 → @16 | 24.0 → 57.1 | 28.7 → 56.7 | equal at saturation |
| **max_seq fit (concurrency slots)** | **24** | **15** | v0.5.2 right-sizes lower ⇒ queues sooner |
| TTFT p50 @16-way | 1302 ms | **6064 ms** | v0.5.2 QUEUES the 16th req (16 > 15 slots) |

*Both arms completed 48/48 at every concurrency level; 64k prefill auto-skipped (ctx 32768). Single run per arm.*

## Read in 20 seconds
- **No regression — entrpi's "no performance re-bases" holds.** On the hot path v0.5.2 is **at least as fast**:
  combined decode +4%, TTFT modestly lower, DSpark acceptance equal. The +4% is within single-run variance
  (n=1, temp 0.7) — call it **neutral-to-slightly-better**, not "4% faster."
- **The real difference is a concurrency trade, not speed.** v0.5.2's serial-session right-sizing reserves more
  memory per sequence → it fits **15 concurrent slots vs v0.5.0's 24**. Aggregate throughput at 16-way is
  unchanged (~57 t/s), but **latency at 16-way blows up** (TTFT p50 1.3 s → 6.1 s, p99 to 33.7 s) because the
  16th request **queues**. For >15-way concurrent serving, v0.5.0 has more headroom; v0.5.2 trades slots for
  deep-serial robustness.
- **Prefill holds better at depth on v0.5.2** (32k PP 964 → 1053 t/s, flat across depth) — consistent with the
  changelog's "long-context requests no longer fall off the CUDA-graph fast path."
- **Verdict: safe to adopt v0.5.2** for the robustness fixes; it's perf-neutral single-stream. Caveat: if you
  serve **>15 concurrent**, its default right-sizing queues — raise the reservation / expect higher tail latency.

## Reproduce (externally repeatable)
```bash
# build both engines (separate checkouts so both binaries persist), sm_121a via make cuda-spark
git clone https://github.com/Entrpi/ds4 && cd ds4 && git checkout v0.5.0 && PATH=/usr/local/cuda/bin:$PATH make cuda-spark
git worktree add ../ds4-052 v0.5.2 && cd ../ds4-052 && PATH=/usr/local/cuda/bin:$PATH make cuda-spark
# weights + drafter: antirez/deepseek-v4-gguf …IQ2XXS…-0731.gguf · bleysg/DeepSeek-V4-Flash-DSpark-drafter-GGUF
# for each arm: serve the SAME weights, vary only DS4_SRC_DIR, then bench
DS4_GGUF_DIR=<gguf> DS4_SRC_DIR=<ds4|ds4-052> ds4-serve -c 32768 --host 0.0.0.0 --port 8000    # DSpark via env-vars
betterbench run --endpoint http://localhost:8000/v1 --model deepseek-v4-flash --max-model-len 32768 --out result.json
betterbench report result.json > report.md
# run both arms sequentially with a clean teardown + memory-return gate between them (one model on the box at a time)
```

## What this card omits / caveats
- **n=1 per arm, temp 0.7** — run-to-run variance is UNMEASURED. The +4% decode / TTFT deltas are within plausible
  single-run noise; the concurrency-slot difference (24 vs 15) is a config fact, not noise.
- **Hot path only** — short ctx, cold nonce, full-residency. v0.5.2's headline fixes (disk-KV restore, deep-`-c`
  serial, dead-client abort) target paths this sweep does NOT exercise; a "no regression here" does not measure them.
- **Quality unchanged assumed, not tested** — this is perf only; v0.5.2 claims byte-exact serving. Not re-verified here.
- **99%-high ITL** columns are warm-cache burst artifacts — read median + 1%-low.

## Concurrency sweep (side-by-side)

Both arms completed **48/48 at every level**. The story is the tail: v0.5.2 fits **15** concurrent slots vs
v0.5.0's **24**, so at **16-way** the 16th request queues on v0.5.2 — aggregate throughput stays equal but TTFT
explodes (p50 6.1 s, p99 33.7 s). Below the slot limit the two are within noise.

| conc. level | agg t/s (v050 → v052) | TTFT p50 ms (v050 → v052) | TTFT p99 ms (v050 → v052) | per-req decode t/s (v050 → v052) |
|--:|--:|--:|--:|--:|
| 1 | 24.0 → 28.7 | 793 → 623 | 1195 → 973 | 27.4 → 32.8 |
| 2 | 29.9 → 30.5 | 837 → 693 | 1640 → 1396 | 15.6 → 15.7 |
| 4 | 41.9 → 43.7 | 835 → 762 | 3139 → 2651 | 11.3 → 11.6 |
| 8 | 51.5 → 52.3 | 942 → 900 | 5429 → 4980 | 7.0 → 7.1 |
| **16** | 57.1 → 56.7 | 1302 → **6064** | 10914 → **33743** | 3.9 → 4.1 |

*max_seq fit: v0.5.0 = 24 slots, v0.5.2 = 15 (right-sized lower for deep-serial reservation). The @16 TTFT blow-up
on v0.5.2 is **queueing** (16 > 15), not slower decode — per-request decode is unchanged (3.9 → 4.1).*

# Glossary
| term | meaning |
|---|---|
| **engine A/B** | same weights/drafter/ctx/harness; ONLY the ds4 engine version differs — isolates the engine as the one variable. |
| **BetterBench** | serving-perf sweep with server-truth token counts (usage from the stream, not a client tokenizer). |
| **TTFT** | time to first token (ms) — latency before generation starts; the queueing tell at high concurrency. |
| **PP t/s** | prompt-processing throughput = prompt tokens ÷ TTFT (prefill speed). |
| **decode t/s** | sustained generation rate once decoding. **ITL 1%-low** = worst-token stutter (t/s); **99%-high** = burst artifact. |
| **DSpark accept** | fraction of drafted tokens the target accepts (lossless spec-decode); workload-dependent. |
| **max_seq fit** | concurrent-sequence slots the engine right-sized to at startup to fit memory (requested 32 → A:24 / B:15). |
| **right-sizing** | v0.5.2's serial-session change reserves more memory per sequence → fewer parallel slots, deeper serial ctx. |
| **IQR / CV** | inter-quartile range / coefficient of variation — spread + run-to-run stability of the decode distribution. |
| **0731 / IQ2XXS** | the DeepSeek-V4-Flash-0731 checkpoint / its ~2-bit imatrix quant (no in-weights MTP → DSpark is the only spec path). |
