
# Report card — BetterBench paired A/B: vLLM 0.23.1 vs 0.25.1, a3b, GB10

> **BetterBench A/B** — *"paired, drift-cancelled A/B measurement … engineered to resolve ~1% differences"*
> (`betterbench ab`: two endpoints, **interleaved one request at a time**, so routing/thermal drift cancels
> and a sub-1% engine delta becomes measurable with a 95% CI). — [BetterBench README](https://github.com/GGZ14/BetterBench)

**What we ran on:** **GB10** (sm_121), driver 580.159.03, kernel `6.17.0-1021-nvidia`. **One variable:** the
vLLM engine image. Same target (a3b-nvfp4), same serve config, both engines **co-tenant** on the one GB10, interleaved.

**Provenance (locked):** **A** = `eugr/spark-vllm:latest` → vLLM `0.23.1rc1.dev1353+g81f51a780` (digest `sha256:b1420ff7…`);
**B** = `eugr-spark-vllm:v25-fi15` → vLLM `0.25.1` (flashinfer-fixed build — this was the previously-**untested** v25
a3b-nvfp4 combo; **served clean**). BetterBench git `3655947`. Config identical A&B (MAXLEN 8192 / modelopt / fp8-KV /
flashinfer), greedy.

> ⚠ **Speed only, and a RELATIVE delta** — this is not an absolute-throughput number (co-tenant, GMU 0.30). Absolute
> a3b decode = the sweep's 73/92 t/s (`reports/2026-07-31-0001`). The A/B isolates *only* the engine-version effect.

## Results — B (0.25.1) vs A (0.23.1)

| metric | mean A | mean B | Δ (B vs A) | 95% CI | verdict |
|---|--:|--:|--:|---|---|
| **decode throughput** (t/s) | 75.66 | 76.15 | **+0.64%** | [+0.54%, +0.74%] | 0.25.1 faster — **significant** |
| **ITL median smoothness** | — | — | **+0.61%** | [+0.40%, +0.82%] | 0.25.1 smoother — **significant** |

Converged in **12 interleaved pairs**: paired CV of the decode diff **0.16%**, CI half-width 0.10% ≤ the 1.0% MDE → auto-stop.

## Read in 20 seconds
- **0.25.1 is measurably faster than 0.23.1 on a3b — by <1%.** Statistically real (the paired method resolves it),
  **operationally negligible.**
- ⇒ **Engine version is not a decode lever** on a3b. Choose the canonical Spark engine on correctness / feature-support /
  stability (0.25 flashinfer breakage, MTP paths, quant support) — **not** this delta.
- The paired mode did exactly its job: it distinguished "significant" from "material," which a pair of noisy separate
  `run`s could not.

## Reproduce (externally repeatable)
```bash
# same target both sides; only the engine image differs. Serve A on :8000, B on :8001 (sequenced — see driver).
#   A img: docker.io/eugr/spark-vllm:latest  (vLLM 0.23.1)   B img: localhost/eugr-spark-vllm:v25-fi15 (0.25.1)
# per engine (identical env), co-tenant GMU 0.30:
VLLM_NVFP4_GEMM_BACKEND=marlin VLLM_MXFP4_USE_MARLIN=1 VLLM_MARLIN_USE_ATOMIC_ADD=1 \
vllm serve nvidia/Qwen3.6-35B-A3B-NVFP4 --revision 491c2f1 --served-model-name a3b \
  --quantization modelopt --kv-cache-dtype fp8 --attention-backend flashinfer \
  --max-model-len 8192 --max-num-seqs 8 --gpu-memory-utilization 0.30 --port 8000   # B: --port 8001, other image
# then the paired A/B (auto-stops at the MDE):
betterbench ab --endpoint-a http://localhost:8000/v1 --endpoint-b http://localhost:8001/v1 \
  --model a3b --mde 1.0 --out ab.json
# sequenced startup (A settles before B) avoids the co-tenant init-OOM
```

## What this card omits
- **Per-category / concurrency / prefill** — `ab` mode measures only the paired decode + ITL deltas (the two numbers
  that resolve a sub-1% engine difference). For the full distribution use single-endpoint `run` (→ `reports/2026-07-31-0001`).
- **Absolute throughput** — deliberately; co-tenant at reduced GMU. Only the *ratio* is the deliverable here.

## Caveats
- **a3b only.** Dense **27b** (where 0.23→0.25 attention/GEMM kernel changes bite harder than on a ~3B-active MoE) may
  show a larger delta — a paired 27b A/B is queued before generalising "0.25 ≈ 0.23 on Spark."
- **Co-tenant, GMU 0.30 / MAXLEN 8192** (down from the sweep's 0.55/32k) after a first attempt OOM'd starting both
  engines at once; fixed with **sequenced startup** (A settles before B). Compute contention under 1-req interleaving
  is minimal, but see the relative-delta caveat above.
- **`provenance.txt` label is stale** — it reads `GMU0.35/MAXLEN32768`; the real served config was GMU 0.30 / MAXLEN
  8192 / MAXSEQS 8 (the served config governs). Corrected in the run's `notes.md`.

# Glossary
| term | meaning |
|---|---|
| **A/B (paired)** | two endpoints measured **interleaved**, request-by-request, so shared drift (thermal, routing) cancels in the difference — resolves deltas a pair of separate runs can't. |
| **decode t/s** | steady-state output tokens/second after the first token. |
| **ITL** | inter-token latency; here compared as median smoothness (lower ms = better, sign-flipped in the tool). |
| **Δ / 95% CI** | percent difference B-vs-A and its 95% confidence interval; "significant" = CI excludes 0. |
| **MDE** | minimum detectable effect — the paired loop keeps sampling until the CI half-width ≤ MDE (here 1.0%), then auto-stops. |
| **paired CV** | coefficient of variation of the per-pair difference; 0.16% here = a very stable delta. |
